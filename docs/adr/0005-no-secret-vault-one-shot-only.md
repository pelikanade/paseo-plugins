# secret-request keeps no vault: one request, one answer, nothing retained

The plugin could store submitted secrets so later sessions and other agents reuse them, and the first draft of this design did exactly that, with grants, expiry, revocation and a settings screen. It was cut. Reuse means a key lives on disk indefinitely, needs an administration surface, and turns every future agent's credential needs into a cross-agent authorization question; the request that motivated the plugin is the opposite: an agent asks, the user answers once, the agent uses the value, and nothing is left to manage. So there is no vault, no grants, no settings screen, no slash command, no reveal, and no reuse — a later session asks again. The only state the plugin keeps on disk is its MCP port and agent token bindings.
