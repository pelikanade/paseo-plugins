# One global vault per daemon

The plugin serves exactly one vault, configured once for the daemon, and no RPC or tool takes a workspace or vault parameter. One credential, one managed directory, one supervised sync process, and one prompt block follow from that, which is most of the plugin's simplicity. The tradeoff is that two Paseo workspaces cannot see two different vaults and a second vault cannot be mounted: adding either later means threading a vault dimension through every contract, every tool name, the settings screen, and the injection cache. Considered and rejected for v0: binding a vault per Paseo workspace, which would duplicate credentials and sync processes per workspace for a feature nobody asked for, and tool-level vault arguments, which push a naming burden onto every agent call before a second vault exists.
