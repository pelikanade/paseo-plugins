# Read-only binds the tools and the sync direction

In v0, "read-only" means two enforceable things: the vault MCP server registers no write tool, and the sync client runs in `pull-only` mode so local changes are ignored and never uploaded. It deliberately does not mean the vault directory is unreachable to the daemon user: the plugin cannot sandbox an agent that already has shell access, and the tools themselves need to read the directory. The decision is recorded because the phrase invites the stronger reading — a future reader will assume agent writes are impossible and may build on that assumption. The strong version would require the whole vault to live outside everything an agent can reach, which contradicts the read tools, or an operating-system sandbox the plugin does not control. Read-write, when it arrives as slice B, changes which tools exist and which sync mode is configured; it does not change this boundary.
