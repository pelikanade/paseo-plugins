# Multi-line secrets are not special-cased: the input strips newlines and the agent repairs

A masked multi-line input does not exist on any target platform. On web, `secureTextEntry` compiles to DOM `type="password"`, and the HTML value sanitization algorithm strips CR/LF from such a field, so a pasted PEM or SSH private key arrives as a single line and the plugin cannot even detect that it was multi-line. On iOS and Android, React Native does not support `secureTextEntry` together with `multiline`, and this repository's E2E harness is web-only, so a native masked multi-line field would ship unverified. The alternatives were a plaintext multi-line mode (the key visible on screen while editing) or a base64 convention the user has to follow. Both were rejected: the plugin stores whatever it receives without reformatting, and the injected agent instruction tells the agent that the field is single-line, that a multi-line secret should be requested with a base64 instruction in `hint` when the agent needs one intact, and that a stripped key is repaired by reading a bounded prefix of the handoff file rather than its whole contents.
