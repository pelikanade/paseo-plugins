# Workspace harness

The checkout pins Paseo CLI, SDK and client to 0.10.2. Its npm server package includes a compiled Web UI, so browser tests need no separate app checkout or bundler. Start `paseo daemon run --home <temporary-home>` with a temporary config containing `daemon.listen: "127.0.0.1:0"`, relay disabled, `features.webUi.enabled: true` and `pluginsEnabled: true`. Read the assigned listener through the pinned server's public `daemon-control` export.

Use the `e2e/` fixture and `*.e2e.mjs` files. `pnpm test` delegates to `pnpm test:e2e`; `pnpm check` includes the complete E2E suite. The workspace's declarative `pkgs.chromium` is discovered on `PATH`; an explicit `PASEO_E2E_BROWSER` can select another compatible system executable. Otherwise install Chromium with `pnpm exec playwright install chromium`. A custom `PLAYWRIGHT_BROWSERS_PATH` can select a browser cache without making the suite optional. Project `PASEO_*` variables are deliberately filtered by the devenv plugin, so do not use them to declare a browser path in `devenv.nix`.

The devenv session scenarios require Linux `/proc`, Bash, Nix, devenv and a real OpenCode executable. They inspect only selected marker variables from the actual OpenCode server processes, without sending a model turn. Tests use temporary `DEVENV_HOME`, XDG data/config/cache directories and copy the repository's pinned `devenv.yaml` and `devenv.lock` into test projects. Never grant trust to the developer checkout from a test. OpenCode persists a session on creation; Codex empty sessions cannot reliably resume before their first turn because there is no saved rollout. Use OpenCode for these credential-free reload scenarios rather than fabricating a Codex rollout.

Scenarios should cover greeting RPC validation and lifecycle, real Greeting UI rendering and invocation, untrusted status without evaluation, explicit trust and automatic reload, changed configuration and manual reload, revocation preventing subsequent injection, invalid Nix and recovery, worktree trust inheritance and native client trust controls. Preserve Bend law/proof and artifact checks under `pnpm verify`; removed finite-trace and mutation unit suites are not retained under an E2E filename.

When adding another plugin, install it through the same fixture and add an externally observable scenario. For source-packaging coverage, install a packed standalone package and invoke it on the daemon rather than asserting file lists.
